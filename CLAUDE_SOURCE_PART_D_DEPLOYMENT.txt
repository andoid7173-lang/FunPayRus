## 🤖 Как выглядит управление

После `/start` администратор получает меню:

```text

Привет! Управляй ботом с помощью кнопок.

[📊 Статус]  [🧩 Плагины]

```

В разделе **«Плагины»** можно включать и отключать плагины, которые **уже установлены** на VPS. Их состояние хранится отдельно от исходного кода.

- Python **3.10+**, Git и доступ к интернету.
- Права `sudo` для установки службы.
- Собственный Telegram-бот, созданный через [@BotFather](https://t.me/BotFather).
- Числовой **Telegram ID** администратора.

## 🚀 Установка на тестовый VPS

**Сначала прочитайте [`install.sh`](install.sh):** скрипт создаёт системного пользователя, каталог конфигурации и службу `systemd`. Выполняйте его только на VPS, предназначенном для FunPay Rust.

Когда доступ к репозиторию настроен, выполните на **новом VPS**:

```bash
sudo apt-get update
sudo apt-get install -y git python3

# Для приватного репозитория требуется настроенный SSH-доступ к GitHub.
git clone git@github.com:andoid7173-lang/FunPayRus.git ~/FunPayRus
sudo mv ~/FunPayRus /opt/funpayrus

cd /opt/funpayrus
sudo bash install.sh
```

Публичный репозиторий можно скачать по HTTPS:

```bash
git clone https://github.com/andoid7173-lang/FunPayRus.git ~/FunPayRus
# Для тестирования v0.3.2b1: cd ~/FunPayRus && git switch feature/read-only-orders-0.3.2-beta
```

Во время установки программа попросит:

1. **Telegram Bot Token** — ввод скрыт.
2. **Telegram ID администратора** — число.

После запуска откройте своего бота и отправьте `/start`.

**Токены и ID не нужно отправлять автору проекта и нельзя публиковать в GitHub.** Конфигурация хранится **только на VPS пользователя** в `/etc/funpayrus/bot.env` с ограниченными правами доступа. При необходимости повторной настройки используйте:

```bash
cd /opt/funpayrus
sudo bash install.sh --reconfigure
```

## 🕹️ Управление службой

```bash
# Статус
sudo systemctl status funpayrus --no-pager

# Перезапуск
sudo systemctl restart funpayrus

# Остановка / запуск
sudo systemctl stop funpayrus
sudo systemctl start funpayrus

# Последние сообщения журнала
sudo journalctl -u funpayrus -n 40 --no-pager
```

Если бот не отвечает, начните с проверки статуса и журнала. **Не публикуйте полный журнал без проверки на наличие личных данных.**

## 🧩 Плагины

Программа ищет плагины в двух местах:

```text
/opt/funpayrus/plugins/       # Плагины, включённые в сам проект
/var/lib/funpayrus/plugins/   # Личные плагины пользователя
```

Пример структуры пользовательского плагина:

```text
plugins/
└── my_plugin/
    ├── manifest.json
    └── plugin.py
```

Пример `manifest.json`:

```json
{
  "name": "Мой плагин",
  "version": "0.1.0",
  "description": "Пример команды",
  "command": "myplugin",
  "enabled": true
}
```

Пример `plugin.py`:

```python
def handle(args: str) -> str:
    return "Плагин работает! 🐱"
```

В v0.3.1b1 внешние плагины по умолчанию **не исполняются**. Разрешение `FUNPAYRUS_ALLOW_EXTERNAL_PLUGINS=1` допустимо только после проверки кода плагина. Подробнее в [SECURITY_TEST_RELEASE.md](SECURITY_TEST_RELEASE.md).

После добавления плагина вручную перезапустите службу:

```bash
sudo systemctl restart funpayrus
```

Команда `/plugins` покажет обнаруженные плагины, а кнопки позволят включать и отключать их. Настройки переключателей записываются в `/var/lib/funpayrus/plugin-state.json` и не должны пропадать при обновлении исходного кода.

> [!CAUTION]
> **Python-плагин — это исполняемый код.** Он может получить доступ к файлам и секретам, доступным процессу бота. Устанавливайте только проверенные плагины. Загрузка ZIP, установка из ссылки и песочница для стороннего кода **пока отсутствуют**.

## 🔄 Обновление из GitHub

```bash
cd /opt/funpayrus
sudo bash scripts/update.sh
```

Скрипт проверяет наличие изменений, показывает новый Git-коммит, запрашивает подтверждение и перезапускает службу. **В тестовой версии добавлены резервное копирование и откат Git-кода после неудачной проверки.** При этом скрипт `scripts/update.sh` рассчитан **только на `main`** и не используется для переключения бета-веток. Для приватного репозитория Git-доступ должен работать и в контексте пользователя, от которого запускается скрипт.

# FunPay Rust v0.3.3b1 — надёжные уведомления (тест)

Только чтение FunPay, без отправки сообщений покупателям и передачи кодов входа.

- Мониторинг проверяет первую страницу продаж примерно каждые 30 секунд при включённой настройке. При HTTP 429 действует пауза 300 секунд. Реальную допустимую частоту следует проверить на сайте.
- Новые оплаченные заказы, а также смены статуса известных заказов (paid, closed, refunded) записываются в SQLite вместе с задачами доставки Telegram. После временной ошибки Telegram задачи повторяются. При падении сразу после успешной отправки возможен дубль: at-least-once, не exactly-once.
- Старые заказы первой успешной синхронизации не уведомляют. Неизвестный заказ, впервые замеченный уже закрытым, не считается новой продажей.
- После 3 последовательных ошибок FunPay владелец получает уведомление; при восстановлении — ещё одно. Это проверка внутри процесса, не внешняя проверка доступности VPS.
- Telegram: /orders now (или «⚡ Проверить сейчас», не чаще одного запроса за 20 секунд); /findorder <ID, покупатель или часть описания> — поиск по локально сохранённой истории; /testalert — безопасное тестовое уведомление.
- Существующие файлы /var/lib/funpayrus/settings.json и orders.sqlite3 сохраняются, схема SQLite расширяется автоматически. Настройки ролей и подписки не сбрасываются.
- Всё ещё экспериментально: HTML FunPay нестабилен; первая страница может пропустить событие; статусы проверяются по CSS карточек. Для автовыдачи эти признаки недостаточны.
- Почтовые коды Steam Guard не извлекаются и не выдаются. Представленный сторонний каркас не использован, потому что он содержит небезопасную логику и не интегрирован с существующим FunPay Rust.

Проверка: python3 -m unittest discover -s tests -v, python3 -m compileall -q bot plugins, bash -n install.sh scripts/*.sh. Обновление с сохранением настроек: cd /opt/funpayrus && sudo bash scripts/update.sh после слияния PR в main. Требуется ручная проверка на Ubuntu VPS.

# FunPay Rust v0.3.2b1 — заказы (тест только на чтение)

**Экспериментальная версия для собственного тестового VPS и разрешённых продаж.**

## Реализовано

- В Telegram у владельца и администратора новая кнопка **«📦 Заказы (тест)»** и команда `/orders`.
- Владелец включает мониторинг кнопкой или `/orders on`; отключает `/orders off`. Настройки сохраняются сразу, **без ручного перезапуска**. По умолчанию мониторинг выключен.
- В **«🔔 Уведомления»** каждый владелец/администратор отдельно включает оповещения о новых оплаченных заказах. По умолчанию выключены. Наблюдатели (`viewer`) не получают покупателей/заказы и не могут включить мониторинг.
- Мониторинг выполняет только GET `https://funpay.com/orders/trade` через Golden Key, уже сохранённый в защищённом `/etc/funpayrus/funpay.env`. Без HTTP-прокси из окружения и без редиректов с ключом, с ограничением размера ответа.
- Каждые ~90 секунд читается **только первая страница** продаж и локально извлекаются ID, статус, короткое описание, покупатель и цена. При HTTP 429 пауза увеличивается до 5 минут; функция не обходит CAPTCHA.
- Информация хранится в SQLite `/var/lib/funpayrus/orders.sqlite3` с режимом `0600`. Старые состояния и подписки сохраняются при обычном обновлении кода.
- **Первый успешный опрос не отправляет уведомлений**, а запоминает уже существующие заказы. Последующие **впервые обнаруженные оплаченные** заказы уведомляют владельца/администраторов, если они включили уведомления. При повторных опросах одно и то же событие не отправляется снова.
- Изменения статусов (`paid`, `closed`, `refunded`) сохраняются в истории, но пока не запускают других действий. `/orders` показывает до 5 последних известных заказов и время последней проверки.
- **Никакого POST к FunPay, сообщений покупателям, автоматической доставки, получения писем Outlook, паролей или кодов входа.**

## Проверка на тестовом VPS

После установки v0.3.2b1 и защищённой настройки Golden Key:

1. Откройте личный Telegram-чат с ботом, нажмите **Заказы (тест)** → **Включить мониторинг**.
2. Подождите первого успешного опроса. Нажмите **Обновить экран**: появится время проверки и число известных заказов. Если есть ошибка, проверьте настройки, сеть и изменения сайта.
3. Откройте **Уведомления** → **Новые оплаченные заказы**. Владелец может добавить второго администратора через `/addadmin ID admin`, тот должен также включить уведомления сам.
4. Выполните **разрешённую реальную тестовую продажу** (без искусственных покупок, нарушающих правила FunPay). После следующего опроса новый оплаченный заказ должен появиться в истории и прислать уведомление подписчикам.
5. Нажмите **Заказы** ещё раз и убедитесь, что повторное уведомление не пришло. По окончании теста: `/orders off`.

**Никогда не публикуйте Golden Key, Telegram Bot Token, данные покупателей, полный SQLite-файл и журналы, содержащие персональную информацию.**

## Ограничения

- FunPay не предоставляет стабильного документированного публичного API, а разбор `tc-item` зависит от текущей HTML-разметки. **На реальном FunPay и реальном VPS интеграция ещё не подтверждена.** При изменении сайта бот может ничего не показать или потребовать обновления парсера.
- Мониторинг работает с первой страницей списка; при большом потоке заказов между опросами часть событий может быть не замечена. Нет гарантии доставки уведомлений при аварийном выключении и сетевых ошибках; запись заказа происходит **до** отправки Telegram-уведомления.
- Проверка статуса основана на отображении продавца: `info` = оплачен, `warning` = возврат, иначе закрыт. Перед любой будущей **автовыдачей** потребуется дополнительно проверять полные сведения о заказе, его статус и принадлежность конкретному продавцу.
- Только владелец управляет работой фонового мониторинга. Привязка нового Golden Key по-прежнему требует безопасного ввода на VPS и однократного перезапуска службы, чтобы systemd перечитал переменные окружения.
- Не предназначено для пересылки логинов, паролей, одноразовых кодов MFA или передачи доступа к почтовым аккаунтам. Для законной автоматической доставки цифровых товаров лучше использовать **собственные лицензионные ключи/коды активации** и разрешённую выдачу после независимого подтверждения оплаты.

## Для разработчиков

# 🐱 FunPay Rus 0.3.0b1 — тестовый релиз безопасности

**Экспериментальная версия.** Изменения предназначены для отдельной тестовой ветки и тестового VPS. Не применяйте без проверки на работающем сервере. Не выполняйте автоматическое объединение PR №2 или этой версии в `main`.

## Что действительно реализовано

- Сохранены существующие Telegram-команды, меню, работа демонстрационного плагина и базовое управление состоянием плагинов.
- Добавлены `/funpay` и кнопка «🔑 FunPay (тест)» для **однократной проверки авторизации на чтение** (кэш ответа 60 секунд). Выполняется только HTTPS GET `https://funpay.com/`. Автосообщения, изменение лотов, обработка и выдача заказов не выполняются.
- `FUNPAY_GOLDEN_KEY` сохраняется **отдельно** в `/etc/funpayrus/funpay.env` (root:funpayrus, 0640), а не в Telegram. Секреты не отображаются в ответах и не публикуются в Git.
- При проверке FunPay используется прямое соединение без прокси из переменных окружения; запрещено следовать HTTP-перенаправлениям с ключом. Ограничен размер ответа; при HTTP 429 проверка прекращается. HTTPS использует стандартную проверку сертификата Python.
- Telegram-обновления фиксируются атомарно в `/var/lib/funpayrus/telegram-offset.json` с правами 0600. **Компромисс:** запись ДО обработки защищает от повторной команды после перезапуска, но в случае аварии после записи событие может потеряться. Это at-most-once, а не полноценное exactly-once.
- Загружаемые Python-плагины из `/var/lib/funpayrus/plugins` сохранены на диске, но в `systemd` **не исполняются по умолчанию**. При повреждённом или подменённом файле состояния плагинов бот отказывается запускаться, чтобы не включить ранее выключенный модуль. Встроенный плагин `hello` продолжает работать. Для доверенных сторонних плагинов требуется ручное включение администратором через `FUNPAYRUS_ALLOW_EXTERNAL_PLUGINS=1` в защищённой конфигурации VPS. Это **не песочница**: после включения плагины смогут читать секреты процесса.
- Состояние плагинов сохраняется через защищённый временный файл и атомарную замену, базовые лимиты на манифест и запрет ссылок.
- Служба systemd дополнительно ограничена (устройства, capabilities, ядро, адресные семейства, пространства имён).
- Обновление из `main` выполняется только в чистом репозитории с подтверждением и резервной копией. При неудаче тестов или старта службы выполняется откат Git-кода. Резервные копии находятся в `/var/backups/funpayrus`, доступ только root.
- CI дополнен `bash -n`; есть автономные тесты FunPay (HTTP-моки) и безопасности.

## Что не протестировано и не гарантировано

- **Не было подключения к реальному FunPay или Telegram**: у тестов используются имитации HTTP и Telegram. Действительный Golden Key не запрашивался.
- FunPay не предоставляет документированного стабильного публичного API. Проверка авторизации зависит от HTML сайта (`user-link-name` и `data-app-data.userId`) и может перестать работать после его изменений или из-за CAPTCHA. Код не пытается обходить защиту.
- Безопасность не может быть гарантирована на 100%. Не проводились pentest, сканирование всей истории Git, интеграционный тест systemd на Ubuntu 24.04 и проверка VPS пользователя.
- `scripts/update.sh` разрешён только в `main`. На отдельной тестовой ветке его **не запускать**. После объединения обновлений в `main` требуется отдельная проверка совместимости конфигурации/службы.
- Старые активные сторонние плагины после установки новой службы будут отключены до ручного разрешения, **не удалены**.
- Секрет доступен Python-процессу, а значит также любому явно разрешённому произвольному плагину. Нельзя включать непроверенные плагины.

#!/usr/bin/env bash
set -Eeuo pipefail

CONF_DIR=/etc/funpayrus
CONF_FILE="$CONF_DIR/funpay.env"
if [[ "$EUID" -ne 0 ]]; then
  echo 'Запустите: sudo bash scripts/configure_funpay.sh' >&2
  exit 1
fi
if [[ ! -d "$CONF_DIR" ]] || ! getent group funpayrus >/dev/null; then
  echo 'Сначала установите FunPay Rus через install.sh.' >&2
  exit 1
fi
if [[ -L "$CONF_FILE" ]]; then
  echo 'Небезопасный путь к файлу конфигурации (ссылка).' >&2
  exit 1
fi
if [[ "${1:-}" == '--remove' ]]; then
  # Avoid shell history exposure; only removes the optional FunPay key file.
  rm -f -- "$CONF_FILE"
  echo 'Golden Key удалён из конфигурации VPS. Для применения перезапустите службу.'
  exit 0
fi
if [[ "${1:-}" != '' ]]; then
  echo 'Использование: sudo bash scripts/configure_funpay.sh [--remove]' >&2
  exit 1
fi
if [[ ! -r /dev/tty ]]; then
  echo 'Нужен интерактивный терминал.' >&2
  exit 1
fi
printf '%s\n' '🔑 FunPay (экспериментальное соединение только для чтения)'
printf '%s\n' 'Ключ останется только в /etc/funpayrus/funpay.env.'
printf '%s\n' 'Не отправляйте Golden Key в Telegram, GitHub или сюда в чат.'
read -r -s -p 'Golden Key (символы скрыты): ' KEY </dev/tty
printf '\n'
if [[ ! "$KEY" =~ ^[A-Za-z0-9_-]{16,256}$ ]]; then
  echo 'Неверный формат Golden Key; данные не записаны.' >&2
  exit 1
fi
umask 077
TMPFILE="$(mktemp "$CONF_DIR/.funpay.env.XXXXXX")"
trap 'rm -f -- "$TMPFILE"' EXIT
printf 'FUNPAY_GOLDEN_KEY=%s\n' "$KEY" > "$TMPFILE"
chown root:funpayrus "$TMPFILE"
chmod 0640 "$TMPFILE"
mv -f "$TMPFILE" "$CONF_FILE"
trap - EXIT
unset KEY
echo '✅ Golden Key сохранён локально.'
echo 'Примените настройку: sudo systemctl restart funpayrus'
echo 'Проверка через личный Telegram-чат: /funpay'

#!/usr/bin/env bash
# Read-only local security diagnostics. Never print secret values.
set -Eeuo pipefail

cd /opt/funpayrus
printf '🔐 FunPay Rus — проверка базовой защиты\n'
if git ls-files | grep -Eq '(^|/)(bot\.env|funpay\.env|\.env|plugin-state\.json)$'; then
  echo '❌ В Git отслеживается файл с потенциальными секретами.' >&2
  exit 1
fi
for file in /etc/funpayrus/bot.env /etc/funpayrus/funpay.env; do
  [[ -e "$file" || -L "$file" ]] || continue
  if [[ -L "$file" ]]; then
    echo "❌ $file является символьной ссылкой." >&2
    exit 1
  fi
  mode="$(stat -c %a "$file")"
  owner="$(stat -c %U:%G "$file")"
  if [[ "$mode" != '640' || "$owner" != 'root:funpayrus' ]]; then
    echo "⚠️ Проверьте права для $file: $mode, $owner" >&2
    exit 1
  fi
  echo "✅ $file: права и владелец соответствуют ожидаемым"
done
if [[ -L /var/lib/funpayrus/plugin-state.json || -L /var/lib/funpayrus/telegram-offset.json ]]; then
  echo '❌ Небезопасная ссылка среди файлов состояния.' >&2
  exit 1
fi
if systemctl is-enabled --quiet funpayrus && systemctl is-active --quiet funpayrus; then
  echo '✅ Служба активна и включена в автозапуск'
else
  echo '⚠️ Служба неактивна или автозапуск выключен'
fi
systemctl show funpayrus --property=NoNewPrivileges --property=ProtectSystem --property=ProtectHome --no-pager
printf '%s\n' 'ℹ️ Проверка не включает сканирование полной истории Git и внешнее проникновение.'

#!/usr/bin/env bash
set -Eeuo pipefail

if [[ "$EUID" -ne 0 ]]; then
  echo 'Запустите: sudo bash scripts/update.sh' >&2
  exit 1
fi
cd /opt/funpayrus
if [[ -n "$(git status --porcelain)" ]]; then
  echo '❌ Есть локальные изменения. Обновление прервано.' >&2
  exit 1
fi
if [[ "$(git branch --show-current)" != "main" ]]; then
  echo '❌ Обновление через этот скрипт разрешено только для main.' >&2
  exit 1
fi
printf 'Проверяем обновления FunPay Rus...\n'
git fetch origin main
CURRENT="$(git rev-parse HEAD)"
LATEST="$(git rev-parse origin/main)"
if [[ "$CURRENT" == "$LATEST" ]]; then
  echo '✅ Уже последняя версия.'
  exit 0
fi
if ! git merge-base --is-ancestor "$CURRENT" "$LATEST"; then
  echo '❌ Невозможно безопасное fast-forward обновление.' >&2
  exit 1
fi
printf 'Текущий коммит: %s\nНовый коммит: %s\n' "$CURRENT" "$LATEST"
read -r -p 'Применить обновление? (yes/no): ' ANSWER </dev/tty
if [[ "$ANSWER" != 'yes' ]]; then
  echo 'Отменено, ничего не изменено.'
  exit 0
fi

umask 077
BACKUP_ROOT=/var/backups/funpayrus
install -d -m 0700 -o root -g root "$BACKUP_ROOT"
BACKUP="$(mktemp -d "$BACKUP_ROOT/preupdate-XXXXXXXX")"
printf '%s\n' "$CURRENT" > "$BACKUP/old-commit.txt"
backup_paths=()
[[ -d /etc/funpayrus ]] && backup_paths+=(etc/funpayrus)
[[ -d /var/lib/funpayrus ]] && backup_paths+=(var/lib/funpayrus)
if (( ${#backup_paths[@]} )); then
  tar -C / -czf "$BACKUP/config-and-user-data.tar.gz" -- "${backup_paths[@]}"
fi
echo "Резервная копия: $BACKUP"

rollback() {
  echo '❌ Обновление не прошло проверку; откатываем только Git-код...' >&2
  if [[ "$(git rev-parse HEAD)" == "$LATEST" ]]; then
    # Checkout started clean, all user data lives outside Git.
    git reset --hard "$CURRENT"
  fi
  if systemctl restart funpayrus && systemctl is-active --quiet funpayrus; then
    echo '✅ Предыдущий код восстановлен, служба работает.' >&2
  else
    echo '⚠️ Предыдущая служба не стартовала; нужна ручная диагностика.' >&2
  fi
  echo "Резервная копия: $BACKUP" >&2
  exit 1
}

if ! git merge --ff-only "$LATEST"; then
  echo '❌ Ошибка Git. Проверьте состояние дерева вручную.' >&2
  exit 1
fi
if ! python3 -m unittest discover -s tests -q || ! python3 -m compileall -q bot plugins || ! bash -n install.sh scripts/*.sh; then
  rollback
fi
if ! systemctl restart funpayrus; then
  rollback
fi
sleep 4
if ! systemctl is-active --quiet funpayrus; then
  rollback
fi
echo '✅ Обновление установлено и прошло основные проверки.'
echo 'Для обновления ограничений systemd после проверки используйте установщик вручную.'

===== END FILE scripts/update.sh =====
