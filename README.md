## 🤖 Как выглядит управление

После `/start` администратор получает меню:

```text
🐱 FunPay Rus v0.3.0b1

Привет! Управляй ботом с помощью кнопок.

[📊 Статус]  [🧩 Плагины]
[🏓 Связь]   [🏠 Главная]
```

В разделе **«Плагины»** можно включать и отключать плагины, которые **уже установлены** на VPS. Их состояние хранится отдельно от исходного кода.

## 📋 Требования

- VPS с Ubuntu 22.04/24.04 или совместимой системой с `systemd`.
- Python **3.10+**, Git и доступ к интернету.
- Права `sudo` для установки службы.
- Собственный Telegram-бот, созданный через [@BotFather](https://t.me/BotFather).
- Числовой **Telegram ID** администратора.

> [!NOTE]
> Репозиторий сейчас может быть **приватным**. В этом случае для `git clone` понадобится предварительно настроить доступ к GitHub (например, SSH deploy key только на чтение). Публичным пользователям он станет доступен для обычного скачивания после открытия репозитория.

## 🚀 Установка на тестовый VPS

**Сначала прочитайте [`install.sh`](install.sh):** скрипт создаёт системного пользователя, каталог конфигурации и службу `systemd`. Выполняйте его только на VPS, предназначенном для FunPay Rus.

Когда доступ к репозиторию настроен, выполните на **новом VPS**:

```bash
sudo apt-get update
sudo apt-get install -y git python3

# Для приватного репозитория требуется настроенный SSH-доступ к GitHub.
git clone git@github.com:andoid7173-lang/FunPayRus.git ~/FunPayRus
sudo mv ~/FunPayRus /opt/funpayrus

cd /opt/funpayrus
sudo bash install.sh
```

Публичный репозиторий можно скачать по HTTPS:

```bash
git clone https://github.com/andoid7173-lang/FunPayRus.git ~/FunPayRus
# Для тестирования беты отдельно: cd ~/FunPayRus && git switch test/security-0.3.0b1
```

Во время установки программа попросит:

1. **Telegram Bot Token** — ввод скрыт.
2. **Telegram ID администратора** — число.

После запуска откройте своего бота и отправьте `/start`.

**Токены и ID не нужно отправлять автору проекта и нельзя публиковать в GitHub.** Конфигурация хранится **только на VPS пользователя** в `/etc/funpayrus/bot.env` с ограниченными правами доступа. При необходимости повторной настройки используйте:

```bash
cd /opt/funpayrus
sudo bash install.sh --reconfigure
```

## 🕹️ Управление службой

```bash
# Статус
sudo systemctl status funpayrus --no-pager

# Перезапуск
sudo systemctl restart funpayrus

# Остановка / запуск
sudo systemctl stop funpayrus
sudo systemctl start funpayrus

# Последние сообщения журнала
sudo journalctl -u funpayrus -n 40 --no-pager
```

Если бот не отвечает, начните с проверки статуса и журнала. **Не публикуйте полный журнал без проверки на наличие личных данных.**

## 🧩 Плагины

Программа ищет плагины в двух местах:

```text
/opt/funpayrus/plugins/       # Плагины, включённые в сам проект
/var/lib/funpayrus/plugins/   # Личные плагины пользователя
```

Пример структуры пользовательского плагина:

```text
plugins/
└── my_plugin/
    ├── manifest.json
    └── plugin.py
```

Пример `manifest.json`:

```json
{
  "name": "Мой плагин",
  "version": "0.1.0",
  "description": "Пример команды",
  "command": "myplugin",
  "enabled": true
}
```

Пример `plugin.py`:

```python
def handle(args: str) -> str:
    return "Плагин работает! 🐱"
```

В v0.3.0b1 внешние плагины по умолчанию **не исполняются**. Разрешение `FUNPAYRUS_ALLOW_EXTERNAL_PLUGINS=1` допустимо только после проверки кода плагина. Подробнее в [SECURITY_TEST_RELEASE.md](SECURITY_TEST_RELEASE.md).

После добавления плагина вручную перезапустите службу:

```bash
sudo systemctl restart funpayrus
```

Команда `/plugins` покажет обнаруженные плагины, а кнопки позволят включать и отключать их. Настройки переключателей записываются в `/var/lib/funpayrus/plugin-state.json` и не должны пропадать при обновлении исходного кода.

> [!CAUTION]
> **Python-плагин — это исполняемый код.** Он может получить доступ к файлам и секретам, доступным процессу бота. Устанавливайте только проверенные плагины. Загрузка ZIP, установка из ссылки и песочница для стороннего кода **пока отсутствуют**.

## 🔄 Обновление из GitHub

```bash
cd /opt/funpayrus
sudo bash scripts/update.sh
```

Скрипт проверяет наличие изменений, показывает новый Git-коммит, запрашивает подтверждение и перезапускает службу. **В тестовой версии добавлены резервное копирование и откат Git-кода после неудачной проверки.** При этом скрипт `scripts/update.sh` рассчитан **только на `main`** и не используется для переключения бета-веток. Для приватного репозитория Git-доступ должен работать и в контексте пользователя, от которого запускается скрипт.

## 🧪 Тесты и разработка

```bash
python3 -m unittest discover -s tests -v
```

Исходники можно редактировать на Windows через Codex или VS Code, например в `D:\FunPayRus`. Не добавляйте файлы с токенами и личной конфигурацией в Git.

Пример структуры:

```text
FunPayRus/
├── bot/                 # Telegram-бот и меню
├── plugins/hello/       # Пример плагина
├── tests/               # Автоматические тесты
├── scripts/update.sh    # Ручное обновление
├── .github/workflows/   # Проверки GitHub Actions
├── install.sh           # Установщик на VPS
├── .env.example         # Шаблон без реальных секретов
├── README.md
└── LICENSE
```
