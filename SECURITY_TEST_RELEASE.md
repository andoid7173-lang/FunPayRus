# 🐱 FunPay Rus 0.3.0b1 — тестовый релиз безопасности

**Экспериментальная версия.** Изменения предназначены для отдельной тестовой ветки и тестового VPS. Не применяйте без проверки на работающем сервере. Не выполняйте автоматическое объединение PR №2 или этой версии в `main`.

## Что действительно реализовано

- Сохранены существующие Telegram-команды, меню, работа демонстрационного плагина и базовое управление состоянием плагинов.
- Добавлены `/funpay` и кнопка «🔑 FunPay (тест)» для **однократной проверки авторизации на чтение** (кэш ответа 60 секунд). Выполняется только HTTPS GET `https://funpay.com/`. Автосообщения, изменение лотов, обработка и выдача заказов не выполняются.
- `FUNPAY_GOLDEN_KEY` сохраняется **отдельно** в `/etc/funpayrus/funpay.env` (root:funpayrus, 0640), а не в Telegram. Секреты не отображаются в ответах и не публикуются в Git.
- При проверке FunPay используется прямое соединение без прокси из переменных окружения; запрещено следовать HTTP-перенаправлениям с ключом. Ограничен размер ответа; при HTTP 429 проверка прекращается. HTTPS использует стандартную проверку сертификата Python.
- Telegram-обновления фиксируются атомарно в `/var/lib/funpayrus/telegram-offset.json` с правами 0600. **Компромисс:** запись ДО обработки защищает от повторной команды после перезапуска, но в случае аварии после записи событие может потеряться. Это at-most-once, а не полноценное exactly-once.
- Загружаемые Python-плагины из `/var/lib/funpayrus/plugins` сохранены на диске, но в `systemd` **не исполняются по умолчанию**. При повреждённом или подменённом файле состояния плагинов бот отказывается запускаться, чтобы не включить ранее выключенный модуль. Встроенный плагин `hello` продолжает работать. Для доверенных сторонних плагинов требуется ручное включение администратором через `FUNPAYRUS_ALLOW_EXTERNAL_PLUGINS=1` в защищённой конфигурации VPS. Это **не песочница**: после включения плагины смогут читать секреты процесса.
- Состояние плагинов сохраняется через защищённый временный файл и атомарную замену, базовые лимиты на манифест и запрет ссылок.
- Служба systemd дополнительно ограничена (устройства, capabilities, ядро, адресные семейства, пространства имён).
- Обновление из `main` выполняется только в чистом репозитории с подтверждением и резервной копией. При неудаче тестов или старта службы выполняется откат Git-кода. Резервные копии находятся в `/var/backups/funpayrus`, доступ только root.
- CI дополнен `bash -n`; есть автономные тесты FunPay (HTTP-моки) и безопасности.

## Что не протестировано и не гарантировано

- **Не было подключения к реальному FunPay или Telegram**: у тестов используются имитации HTTP и Telegram. Действительный Golden Key не запрашивался.
- FunPay не предоставляет документированного стабильного публичного API. Проверка авторизации зависит от HTML сайта (`user-link-name` и `data-app-data.userId`) и может перестать работать после его изменений или из-за CAPTCHA. Код не пытается обходить защиту.
- Безопасность не может быть гарантирована на 100%. Не проводились pentest, сканирование всей истории Git, интеграционный тест systemd на Ubuntu 24.04 и проверка VPS пользователя.
- `scripts/update.sh` разрешён только в `main`. На отдельной тестовой ветке его **не запускать**. После объединения обновлений в `main` требуется отдельная проверка совместимости конфигурации/службы.
- Старые активные сторонние плагины после установки новой службы будут отключены до ручного разрешения, **не удалены**.
- Секрет доступен Python-процессу, а значит также любому явно разрешённому произвольному плагину. Нельзя включать непроверенные плагины.

## Применение к существующему проекту — только локально

На **Windows**, в PowerShell:

```powershell
cd D:\FunPayRus
git status --short                 # убедиться, что нет локальных изменений
git switch main
git pull --ff-only
git switch -c test/security-0.3.0b1
```

Распакуйте архив обновления **за пределами** каталога проекта. Из каталога распакованного архива:

```powershell
python apply_beta.py --target D:\FunPayRus
cd D:\FunPayRus
python -m unittest discover -s tests -v
git diff --check
git status --short
git add bot scripts tests .github SECURITY_TEST_RELEASE.md install.sh
git commit -m "test: security hardening and read-only FunPay probe"
```

`apply_beta.py` прекращает работу, если checkout не является чистой отдельной веткой. Он делает резервную копию заменяемых файлов **кода** рядом с локальным репозиторием. Он не меняет VPS, GitHub или пользовательские секреты.

**PR №2** остаётся Draft. В этом пакете уже есть аналог исправления версии установщика, поэтому перед объединением PR №2 сравните изменения, чтобы не получить конфликт.

## Тестовый Ubuntu 24.04 VPS

После переноса и checkout **тестовой ветки** в `/opt/funpayrus`:

```bash
cd /opt/funpayrus
python3 -m unittest discover -s tests -v
python3 -m compileall -q bot plugins
bash -n install.sh scripts/*.sh
sudo bash install.sh
```

Эта последняя команда действительно перезапустит службу **на том VPS, где она выполняется**. Не используйте её на рабочем сервере до отдельного решения.

Если хотите проверить авторизацию FunPay, вводите собственный Golden Key **только на тестовом VPS**:

```bash
sudo bash scripts/configure_funpay.sh
sudo systemctl restart funpayrus
sudo bash scripts/security_check.sh
```

Затем откройте **личный** Telegram-чат с ботом: `/start`, `/ping`, `/plugins`, `/funpay`. Если ключ не указан, `/funpay` сообщит, как его установить, и не выполнит запрос к FunPay. Для отключения теста:

```bash
sudo bash scripts/configure_funpay.sh --remove
sudo systemctl restart funpayrus
```
