# FunPay Rust 0.3.1b1 — расширенная Telegram-панель

**Экспериментальная версия.** Код добавляется отдельным Pull Request. Действующий VPS, Golden Key и основная ветка `main` не изменяются автоматически.

## Что действительно реализовано

- В меню есть **Статус**, **Диагностика**, **FunPay (тест)**, **Демо**, **Уведомления**, **Настройка** и **Администраторы** (для владельца).
- Поддерживаются `owner`, `admin`, `viewer` в **личных чатах Telegram**. Только владелец может менять роли, включать плагины и исполнять команды плагинов. Роль `admin` может проверять FunPay, `viewer` видит только общие экраны и демо.
- Владелец добавляет второго человека командой `/addadmin 123456789 viewer` или `/addadmin 123456789 admin`, удаляет `/removeadmin 123456789`. Друг должен открыть чат с ботом и нажать `/start`. Максимум пять дополнительных пользователей.
- Роли и настройки уведомлений записываются атомарно в `/var/lib/funpayrus/settings.json` с режимом `0600`. Повреждение файла или ссылка на файл **останавливают запуск**, а не предоставляют доступ.
- Для каждого пользователя включаются уведомления **о запуске службы** (кнопка «Уведомления»). Они выключены по умолчанию и действуют со следующего запуска. **Уведомлений о заказах пока нет.**
- `/diagnostics` показывает локальное состояние хранилища, диска, количество плагинов и ошибки загрузки, статус *настройки* ключа. Он **не** подтверждает непрерывную доступность FunPay или VPS. Полный сбой VPS требует стороннего мониторинга.
- `/demo` показывает только явно подписанные *вымышленные* заказы, не обращаясь к FunPay.
- `/setup` показывает этапы настройки и безопасный способ ввода ключа через VPS. Ключ по-прежнему нельзя отправлять боту через Telegram.
- Никаких новых неофициальных операций с заказами, сообщений покупателям и выдач товаров в релизе нет.
- Имя в интерфейсе изменено на «FunPay Rust», а пути `/opt/funpayrus`, `/etc/funpayrus`, `/var/lib/funpayrus`, `funpayrus.service` **сохранены** для совместимости. Репозиторий GitHub также пока называется `FunPayRus`.
- `systemd` уже содержит `Restart=on-failure`: это автоматическое восстановление **процесса**, но не защита от отключения всей машины. Изменение ролей и уведомлений **не требует перезапуска**. Обновление Python-кода и перечитывание файла Golden Key — требуют автоматического/ручного перезапуска процесса.

## Команды

Владелец: `/admins`, `/addadmin ID [admin|viewer]`, `/removeadmin ID`, `/plugins`.

Все зарегистрированные пользователи: `/start`, `/menu`, `/status`, `/diagnostics`, `/notifications`, `/demo`, `/setup`, `/ping`. `/funpay` доступен владельцу и роли admin.

## Ограничения

Это **не** завершённый магазин плагинов, бот-приёмник идей, обработчик заказов, полноценный установщик одной командой или внешняя система мониторинга. Нельзя считать локальную диагностику доказательством состояния VPS вне процесса бота. Безопасность не гарантируется; непроверенные Python-плагины не должны запускаться с доступом к секретам.

После проверки GitHub Actions и на тестовом Ubuntu 24.04 VPS выпуск можно отдельно рассмотреть для `main`. Выполняйте команды установки только на своём тестовом VPS; никакого автоматического развёртывания из Pull Request нет.
