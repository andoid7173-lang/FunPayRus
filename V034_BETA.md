# v0.3.4b1: очередь ручной проверки

Добавлены SQLite-очередь review_queue, команда /queue, кнопка «Очередь проверки» и /queue done ID для владельца. Первое сканирование добавляет кандидатов для сверки без уведомлений о старых заказах. Дубли не создаются при повторных опросах. Если текущий HTML-статус меняется на closed или refunded, ещё не завершённая задача блокируется. Повторный paid её не разблокирует.

## Что НЕ сделано

Нет подтверждения оплаты через официальный API, автовыдачи, автоответов покупателю, Steam-интеграции или управления лотами. Статус paid определяется только HTML первой страницы заказов. Он НЕ подтверждает оплату, поэтому каждую заявку нужно проверять на сайте FunPay вручную. /queue done ID лишь записывает в SQLite, что владелец самостоятельно выполнил заказ; сообщений покупателю она не отправляет.

## Проверка

На локальной копии: python3 -m unittest discover -s tests -v. На тестовом VPS: /start, /orders on, /queue. В /demo реальные заявки не создаются. Вся установка описана в README.
